# Milestones

## Purpose

This document sets milestone-level targets for Ace as a product and platform.

## Ace 1.0

Theme:

- credible first release of the Ace branch-tree workflow layer

Must include:

- dependable `git ace` core workflows
- honest and current documentation
- clear separation between stable and experimental commands
- Git-native compatibility story that is easy to explain

Can still be incomplete:

- advanced review-series workflows
- richer agent-native orchestration
- fully mature `git history` / `git replay` / `git backfill` story

Success statement:

- Ace 1.0 is the release where users can reasonably say, "this fork has a real core idea and I can trust its main workflow surface."

## Ace 1.1

Theme:

- sharpen the adjacent workflow tools around the core Ace branch-tree model

Target areas:

- stronger `git history` and `git replay` safety and preview behavior
- better repository introspection via `git repo`, `git refs`, and `git last-modified`
- stronger test coverage around ref, metadata, and history-affecting workflows
- improved operator-facing diagnostics

Success statement:

- Ace 1.1 is the release where the fork starts to feel like a coherent workflow toolkit rather than a strong central feature plus a set of experiments.

## Ace 2.0

Theme:

- become a true Git-native workflow platform

Target areas:

- first-class review-series management
- stronger agent-native collaboration surfaces
- better conflict-management UX
- workflow intent as structured data
- more operator-grade repository health and policy tooling

Success statement:

- Ace 2.0 is the release where the project clearly delivers capabilities standard Git still does not model well, without sacrificing sovereignty or compatibility.

## Milestone Rule

- 1.0 should establish trust.
- 1.1 should establish coherence.
- 2.0 should establish differentiation.
