# Roles And Owners

## Purpose

This document makes the current AcreetionOS co-lead ownership model explicit for the Ace repository.

It does not imply rigid exclusivity. It shows who should be treated as the primary owner or co-owner for each major organizational function until the contributor base grows.

## Current Co-Leads

- `Darren Clift`
- `Natalie Cole-Clift Spiva`

## Ownership Model

## Darren Clift

Primary areas:

- Executive / Strategy
- Product
- Core Engineering
- Operations / Reliability
- Release Management
- Sustainability / Strategy

Supporting areas:

- Security
- Performance Engineering
- Ecosystem / Integrations
- Community / Developer Relations

Working interpretation:

- Darren should be treated as a primary owner for long-term direction, operational practicality, and the durability of the platform.

## Natalie Cole-Clift Spiva

Primary areas:

- Executive / Strategy
- Product
- Design / UX
- Core Engineering
- Developer Experience
- Documentation
- Ecosystem / Integrations

Supporting areas:

- QA / Test Engineering
- Release Management
- Security
- Community / Developer Relations
- Sustainability / Strategy

Working interpretation:

- Natalie should be treated as a primary owner for product articulation, user/developer experience, documentation clarity, and the visible shape of the Ace workflow platform.

## Shared Critical Functions

The following functions should be treated as shared co-lead responsibilities:

- strategic direction
- release posture
- compatibility decisions
- experimental versus stable labeling
- governance-sensitive public positioning

## Contributor Growth Rule

As AcreetionOS grows, this document should be updated so ownership becomes more distributed and less dependent on the co-leads personally.

## Bottom Line

Right now, Ace is best understood as a co-led project where Darren and Natalie jointly cover the responsibilities that a larger open community organization would eventually distribute across a broader team.
