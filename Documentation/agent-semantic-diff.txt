Agent Semantic Diff Format
==========================

The semantic diff is a JSON-encoded summary of what changed between
two commits, stored as a blob under `refs/agent/commits/<sha>/diff-summary`.

Unlike a unified diff, the semantic diff describes *intent*: function
renames, extractions, modifications, deletions, and configuration
changes.  This format is designed for AI agents with limited context
windows who cannot afford to read full textual diffs.


Schema Version 1
----------------

Top-level object:

| Field | Type | Description |
|---|---|---|
| `schema` | string | Always `"1"` for this version. |
| `base` | string | Base commit object name (or empty for unstaged). |
| `head` | string | Head commit object name (or empty for working tree). |
| `token_estimate` | integer | Rough token count of the full textual diff. |
| `changes` | array | List of change descriptor objects. |

Each element of `changes` is an object with at least the field `type`.
The other fields depend on the change type:

### `add-file`

| Field | Type | Description |
|---|---|---|
| `type` | string | `"add-file"` |
| `path` | string | Added file path. |
| `description` | string | Human-readable summary. |

### `delete-file`

| Field | Type | Description |
|---|---|---|
| `type` | string | `"delete-file"` |
| `path` | string | Deleted file path. |

### `rename`

| Field | Type | Description |
|---|---|---|
| `type` | string | `"rename"` |
| `from` | string | Old path. |
| `to` | string | New path. |
| `score` | integer | Rename similarity score (0-100). |

### `modify`

| Field | Type | Description |
|---|---|---|
| `type` | string | `"modify"` |
| `path` | string | Modified file path. |
| `old_size` | integer | Old file size in bytes. |
| `new_size` | integer | New file size in bytes. |

### `unknown`

| Field | Type | Description |
|---|---|---|
| `type` | string | `"unknown"` |
| `description` | string | Fallback description. |


Example
-------

```json
{
  "schema": "1",
  "base": "abc123",
  "head": "def456",
  "token_estimate": 312,
  "changes": [
    {
      "type": "rename",
      "from": "auth.c",
      "to": "auth_v2.c",
      "score": 78
    },
    {
      "type": "add-file",
      "path": "jwt.c",
      "description": "JWT parsing extracted here"
    },
    {
      "type": "modify",
      "path": "auth_v2.c",
      "old_size": 1240,
      "new_size": 890
    }
  ]
}
```


Generation
----------

The semantic diff is generated by `builtin/agent-diff.c` from a
`diff_queue_struct`.  The generator does not need to be perfect;
partial coverage is acceptable.  Changes that cannot be classified
fall back to `{"type": "unknown", "description": "..."}`.

The `token_estimate` is a rough heuristic: one token per four bytes
of diff text.  It is intended to help agents decide whether to fetch
the full diff or rely on the summary.


Consumption
-----------

Tools that consume semantic diffs MUST accept unknown `type` values
gracefully.  Future schema versions may introduce new change types.
